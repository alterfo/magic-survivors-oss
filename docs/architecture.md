# Архитектура

Один `MonoBehaviour` — `Game` (partial-класс в нескольких файлах). Враги, снаряды, кристаллы — простые классы без своих `Update`: весь апдейт идёт из `Game.Update`, так сотни скелетов не тормозят.

| Файл | Зона |
|---|---|
| `Assets/Scripts/Game.cs` | ядро: состояния, шаг мира, спавн волн, враги, урон, снаряды, лужи, камера, `OnGUI` |
| `GameMenu.cs` | стартовый экран: каталоги `Levels` / `Heroes`, выбор, `Restart(toMenu)` |
| `GameUI.cs` | карточки прокачки/суперсил/сундуков, HUD, экран статов, конец забега |
| `GameText.cs` | шрифты, стили, плашки, обводка текста, подсветка чисел |
| `GameLoot.cs` | ярость, 5 размеров кристаллов, реликвии на поле, пауза и настройки, пресет графики |
| `GameBot.cs` | автопилот для прогона баланса (`Game.bot`, timeScale 6, лог срезов) |
| `GameLook.cs` | окно героя → «Облик»: полки одежды по слотам на живой модели, фильтр «моё и по карману» |
| `Skills.cs` | заклинания, пассивки, слияния; `Desc(level)` даёт текст карты |
| `Artifacts.cs` | артефакты из сундуков (лямбда `apply`) |
| `Entities.cs` | `Player`, `Enemy`, `Proj`, `Gem`, `BurnPool`, `Artifact` |
| `World.cs` | загрузка моделей KayKit, земля, декор, коллизии с декором (капсулы), свет, главы |
| `Vfx.cs` | глобальные системы частиц (`Emit`), вспышки, молнии, пятна, шипы-сосульки/камни (процедурные меши) |
| `Art.cs`, `Gen.cs` | текстуры из Resources, процедурные спрайты |
| `Assets/Editor/Builder.cs` | сборки под все платформы |

Состояния: `Menu → Play ⇄ LevelUp / Super / Chest / Stats / Pause → Dead | Won`. В любом состоянии кроме `Play` мир стоит (dt = 0).

Интерфейс — IMGUI в условных пикселях: альбом — 1080 по высоте, вертикальный телефон — 760 по ширине (`UiScale`). Событие `Layout` пропускается, кнопки — `GUI.Button` поверх нарисованных плашек.

Производительность: скелет склеивается в один `SkinnedMeshRenderer`, аниматоры мобов вне кадра выключены, материалы кэшируются ради SRP Batcher, пулы для всего что спавнится, `renderScale` держит высоту кадра ~1200/800 px.

Частота кадров по месту (`FrameRateTick` в `GameLoot.cs`, с 16.11): полная (настройка, на телефоне по умолчанию 30, на ПК 60) — только в бою и на прогулке по городу; меню, окна, пауза, выбор карт — 30; окно без фокуса — 15. По телеметрии логика стоит 0,2–2 мс на кадр, интерфейс 0,5–6 мс, остальное — отрисовка сцены.

Низкая графика (по умолчанию в браузере и на телефонах, `ApplyQuality` в `GameLoot.cs` + `World.SetQuality`): без теней и MSAA, FXAA вместо SMAA (на телефоне без сглаживания), свечение с четверти кадра, до 4 (телефон — 2) точечных источников, 2 (телефон — 1) кости на вершину, короткая сторона кадра 800 (телефон — 640) px. Автоподстройка `AdaptTick`: в бою при кадрах ниже 72% цели кадр мельчает шагами по 12% до 60%; шаг, не давший +8% кадров, откатывается и подстройка выключается до перезапуска (значит, упёрлись не в видеокарту).

Замер: срезы телеметрии несут `rs` (масштаб рендера, %), `sim` и `gui` (десятые доли мс на логику с анимацией и на OnGUI). Локально — `MagicSurvivors.app --args -autoplay -solo [-timescale 2] -logFile /tmp/solo.log`, в логе строки `perf:` раз в 10 с. Замер 2026-11-11 на Mac при 240 скелетах: логика 2.3 мс, интерфейс 0.5 мс — код не узкое место; телефоны в телеметрии дают 20–28 FPS уже при 20 мобах, то есть упираются в отрисовку.
